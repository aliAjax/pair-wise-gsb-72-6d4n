# 功能开关灰度发布与影响审阅平台

基于 React 的本地可运行前端工程，覆盖功能开关配置、影响评审、依赖分析、灰度时间线、冻结回滚和发布报告。业务数据由 RTK Query 端点驱动，并持久化到浏览器 `localStorage`。

## 技术栈

- React 18 + TypeScript + Vite
- MUI
- Redux Toolkit
- RTK Query
- React Router

## 启动

```bash
npm install
npm run dev
```

默认开发地址为 `http://localhost:18472`。

## 构建

```bash
npm run build
npm run preview
```

## 工作区

- 发布概览：开关采用趋势、环境放量差异、阻断问题和待评审项
- 功能开关：按状态、环境、团队和关键字筛选，进入完整配置编辑器
- 影响评审：逐项检查规则冲突、死代码、指标缺失、实验重叠和客户端兼容
- 依赖关系：依赖影响图、互斥冲突矩阵和降级关系
- 灰度发布：分阶段放量、环境差异、指标守护、冻结和紧急回滚
- 发布批次：同一 Key 的开发/预发/生产收成一批，锁定来源环境、依赖开关、最低客户端版本与灰度阶段；多窗口批准、漂移失效、双窗口裁决、发布前三闸门与整批回滚
- 审计与回滚：查询调整、审批和异常事件，记录受影响用户范围
- 发布报告：查看发布明细并导出 CSV

浏览器首次打开时会自动写入示例数据。编辑、审批、灰度和回滚操作会写入 `feature-flag-release-console-v1` 对应的本地存储键。

## 多环境发布批次规则

- **建批次即锁定**：创建时记录来源环境、各环境依赖开关状态、最低客户端版本、受众规则和灰度阶段快照及来源指纹。
- **批准前改动即失效**：批次处于批准收集中时，任一环境的受众、依赖、版本或灰度阶段再被改动（含开关编辑器保存、审批、回滚或绕过批次单独放量），候选立即变为「已失效」；可基于当前实时配置重建，旧状态与审计仍可查。
- **独立确认窗口**：开发、预发、生产各自有批准窗口；两个窗口同时批准同一 Key 的两个候选时，原子裁决只保留创建更早的一个有效批次，另一个标记「已被取代」（页面顶部可模拟该并发）。
- **发布前三闸门**：全部窗口批准后，整批校验①依赖开关是否被回滚/关闭、②环境客户端基线是否低于锁定最低版本、③灰度顺序是否冲突（上游实时流量低于下游锁定阶段）。任一不通过整批停在「待处理」；修复（恢复依赖、同步基线、对齐上游灰度）后重新校验，已完成的环境确认项保留。
- **整批发布与回滚**：发布按 开发 → 预发 → 生产 顺序写入锁定配置并留存发布前还原点；整批回滚一起恢复各环境当时的受众规则、依赖开关状态与灰度阶段，批次历史和审计记录全程留存。
